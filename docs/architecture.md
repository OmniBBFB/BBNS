# 系统架构与模块依赖

BBNS 是个人订阅日报工具：采集有限来源，保留来源顺序和原生排名，生成摘要并定时推送，支持网页阅读历史。事件追踪用于补充背景与变化，不执行重要度过滤、自动合并推送或重排。

## 已部署入口与新流程

原有 `src/scheduler-cli.mjs` 和 systemd 服务入口保留，负责目前已部署的 collect → summarize → push。新流程 v2 已提供代码与离线测试，但需要按部署协议显式切换；新增代码不会替旧定时器发送。

新流程为 collect → prepare → edit → track → compose → push。只新增事件追踪业务模块，其余阶段归原有模块或任务适配层。不同入口不是长期并行的产品功能；旧服务切换并确认原有任务结清后，应另行退役旧执行入口，旧归档读取仍须保留。

## 模块职责

| 模块 | 拥有的职责 | 不承担的职责 |
| --- | --- | --- |
| 调度内核 | 计划期次、依赖、超时、重试、状态、产物引用 | 不解析 SourceMessage、Fact、Story 或渠道正文 |
| 任务适配与流程编排 | 固定日报窗口，选择输入，读取历史，调用各模块，保存结果，组合期次，转换推送文本 | 不把语义关联算法塞入调度器 |
| 订阅与采集 | 来源策略与单次网络采集，输出 SourceMessage 与来源结果 | 不保存、不调模型、不自行调度 |
| AIGC 编辑 | 逐条摘要，结构化事实与证据，输出覆盖及原文匹配校验 | 不自行查询历史、采集、归档或推送 |
| AI 推理 | 模型供应商请求及返回值 | 不决定归组、不内置循环重试 |
| 事件追踪 | 传入历史中的候选召回、关系判断、复核、来源对照、进展 | 不自行读写历史、不运行定时器、不丢弃或重排消息 |
| 存储 | 原始批次、稳定身份、版本、事件关系、判断、期次与投递记录 | 不通过数据库查询替代语义判断；新闻正文不进入调度账本 |
| 消息推送 | push/reply/入站处理，企微 Adapter，连接与回执 | 不决定日报内容、窗口或事件归属 |
| 后端查询与前端 | 只读归档与当前事件证据，呈现新闻、摘要、进展和时间 | 阅读不触发采集、模型调用或业务写入 |

模块允许网络和存储副作用，不是全都为数学纯函数；共同约束是单次调用、依赖显式注入、没有隐藏调度与重试。

## 数据流与持久化

编排将采集记录保存为不可变原始 JSONL，登记业务内容库，固定期次输入，然后依次编辑、追踪并归档。推送与网页以正式 SummaryDocument 为当期内容事实源。

业务内容 SQLite 独立于调度 SQLite，保存 Article 身份、版本、发现/基线、Fact/Story、证据、判断和阶段结果。GitHub 榜单使用独立观测身份，不被强制映射成新闻事实。

文件发布与 SQLite 不是跨介质原子事务。正式文档使用稳定期次任务 ID 和内容哈希：文档存在时核对并复用；索引缺失时根据同一文档补登记，不重新生成不同内容。调度账本继续只保存执行状态和引用。

## 不变约束

1. 采集不依赖 AI 推理，编辑不依赖推送，消息模块不依赖个人 agent 业务。
2. 各来源条数、顺序和排名由程序保留，模型不能删除或重排。
3. 人工 agent 仍通过可替换入站 handler 接入；当前 handler 仍可返回 todo。
4. accepted 只表示渠道接受，unknown 不自动重发。
5. 旧归档不重写、不自动批量重新总结或补发；新期次采用版本化契约。
6. 新流程所有必需任务继续按失败阻断依赖；未新增自动降级。
