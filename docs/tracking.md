# 事实抽取与事件追踪

本轮实现的是可独立调用的个人资讯处理流程 v2。只有显式使用 `src/workflow-cli.mjs` 才会执行；当前安装的旧定时服务不会自动切换。

## 职责与接口

- AIGC 编辑：`extractMessages(messages, {client, signal})`，输出保序的摘要、零到多个事实候选和证据。实现位于 `src/editorial.mjs`。
- AI 推理：仍使用注入的 `client.complete`；供应商 client 不理解归组或调度。
- 事件追踪：`track({current, historicalCandidates}, {client, signal})`，输出关系、Fact/Story 归属、进展和来源对照。实现位于 `src/tracking.mjs`，不读取数据库、不保存历史、不内置时钟和重试。
- 编排：`src/workflow-handlers.mjs` 读取并固定历史集合，保存模型回执结果和阶段产物，调用存储应用关系；`src/workflow.mjs` 只负责装配。
- 存储：`ContentStore` 维护身份、版本和关系约束；`ContentReader` 使用 SQLite 只读模式提供当前事件投影。

这是一套逻辑模块划分，不是微服务。没有增加重要度评分、筛选门槛、自动重排、Embedding 供应商或消息中间件。

## 领域记录

| 记录 | 含义 |
| --- | --- |
| SourceMessage | 一次采集记录；UUID 仅作追踪，不作稳定身份 |
| Article | 来源命名空间内的一份报道，优先原生条目标识，其次原文 URL；无稳定键时不按标题猜测去重 |
| ArticleRevision | 本地观察到的内容版本，保存源消息、内容哈希和版本号；不是原站完整编辑历史 |
| ObservationSnapshot | 榜单等观测按来源、条目、当地观测日建立身份；每天同一仓库都可以出现 |
| Fact | 一次具体发生或待核对主张，不代表已经证实为真 |
| Story | 具体事件及其直接进展，不是同一公司/产品所有新闻的集合 |
| Evidence | 原文连续片段及其字符起止位置，引用明确的文章版本 |
| SummaryDocument v2 | 固定某一期的窗口、输入、摘要、事实关系和诊断，不跟随当前事件状态改写 |

## 事实抽取

输入完整保留来源顺序与排名；模型返回每条输入的摘要、scope 和 facts。非 article 类型必须 `facts=[]`。综合稿可以拆成多个有证据的具体动作，不能把多话题强行归成一个发生。

证据必须能连续匹配输入原文；允许跨空白的匹配，但保存匹配到的原始文本和位置。找不到的核心证据对应的事实候选被丢弃，并记录 `ungrounded_evidence`，消息本身和摘要仍保留。找不到的条件不展示，并记录诊断。

发生日期只接受原文明示日期和可回到原文的时间证据；不以文章发布时间补齐。首版日期证据识别 ISO、中文年月日和斜线日期；无法确认就保留 null。

## 关系判断与复核

对传入的历史事实及本批已判断结果，使用标题/主体/动作/对象的字符二元组相似度和相同原文 URL 线索召回候选。首版每次模型判断最多八个候选，这是控制提示词规模的实现上限，不是重要度门槛或评测结果。

关系包括：

- `SAME_OCCURRENCE`：同一次发生，复用 Fact 与 Story。
- `SAME_STORY`：直接后续，创建新 Fact，复用 Story。
- `UNRELATED`：无关，建立独立记录。
- `ROUNDUP`：无法归为同一次发生的综合材料，保持独立。
- `UNRESOLVED`：材料不足或复核未确认，保持独立并提示关系未确定。

模型不能引用未提供的目标。拟关联的判断必须有双方可匹配的原文片段，再进行一次模型复核。复核不确认或关系不一致时，记录未确定，不强行合并。历史不足时直接新建，不额外调用关系模型。

没有根据实际标注样本宣称准确率；LLM 的置信或重复回答都不是事实真伪证明。首版没有大规模历史检索索引或长期自动调查。

## 来源交叉对照

关系判别另外输出一致、补充、冲突或未知，独立于是否同一个事件。对照结论只有在双方引文均可匹配原文时保留。

明确相同的原文/原发引用 URL 标为 `shared_origin`；没有这种证据时标为 `unknown`。**不同来源 ID 或不同域名不会被当成已经核实的独立信源**。首版可以保存 `data.origin_url`、`data.publisher_url`、`data.references` 中的显式线索，但不自动上网调查原发链。来源独立核验的自动覆盖仍有限，不能将其描述为完整事实核查系统。

## 可恢复处理与查询

模型成功返回后先保存结果，再进行后续处理；成功结果按模型身份、提示词版本和输入哈希复用。历史集合在首次追踪前固定，重试不会悄悄换上下文。第三方返回之前中断仍可能重复计费。

关联结果应用在事务中，同一修订的重复应用必须一致；错误目标或冲突重放会失败。当前事件查询通过内部 `GET /api/stories/<story-id>` 读取已经保存的证据，不调用模型；历史日报展示的是当时冻结的关系。

测试使用本地假模型和静态材料，覆盖同次发生、后续进展、复核拒绝、伪造引文、目标越界、转载线索和跨期恢复。测试通过不表示真实模型关联质量已经实测。
